### 跨域原因

跨域问题（Cross-Origin Resource Sharing, CORS）主要是由于==浏览器==实施的安全策略引起的。这种安全机制被称为“同源策略”（Same-origin policy），它限制了一个Web页面从不同的源（域名、协议或端口）获取资源的能力。

当一个网页尝试从不同于自身来源的其他来源请求数据时，就会遇到跨域问题。这是因为现代浏览器为了防止恶意脚本从其他不受信任的站点窃取用户数据，采取了严格的限制措施。例如，一个运行在`example.com`上的JavaScript脚本，默认情况下不能请求`anotherdomain.net`上的资源，除非后者明确表示允许这样做。

以下是一些场景，其中浏览器的同源策略会导致跨域问题：

1. **前端应用与后端服务分离**：现代Web应用常常将前端（客户端）与后端（服务器端）分离部署在不同的域名下，这使得前后端之间的请求成为了跨域请求。

2. **API调用**：当一个Web应用需要从第三方API获取数据时，如果这些API部署在不同的服务器上，那么就需要处理跨域问题。

3. **多服务器架构**：在一些复杂的应用程序中，可能涉及到多个服务器之间的通信，每个服务器可能位于不同的域名下。

为了使跨域请求合法，==服务器需要通过响应头中的`Access-Control-Allow-Origin`来指定哪些源（即域名）可以访问其资源==。如果服务器响应中包含正确的CORS头部信息，浏览器就会允许该请求继续进行；否则，浏览器会阻止该请求，并抛出错误提示。

总之，跨域问题是出于安全考虑而设计的机制的一部分，它要求开发者在设计API时考虑到来源的安全性，并在服务器端正确配置CORS头来允许跨域请求。

### spring中解决

在Spring Boot项目中解决跨域问题通常可以通过使用CORS（Cross-Origin Resource Sharing，跨源资源共享）来实现。Spring框架提供了多种方式来支持CORS，包括使用`@CrossOrigin`注解以及通过配置全局的CORS拦截器。以下是两种常见的方法：

#### 方法一：使用`@CrossOrigin`注解

在控制器类或特定的方法上使用`@CrossOrigin`注解可以允许指定的来源访问你的API。

示例代码：

```java
import org.springframework.web.bind.annotation.CrossOrigin;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class MyController {

    @CrossOrigin(origins = "http://example.com")
    @GetMapping("/api/data")
    public Object getData() {
        // 处理逻辑...
        return "Some Data";
    }
}
```

在这个例子中，`http://example.com`是允许访问此端点的唯一来源。如果需要允许所有来源，则可以将`origins`设置为`"*"`。

#### 方法二：全局配置CORS

如果你希望对整个应用程序的所有请求都支持CORS，那么可以在Spring MVC中添加一个全局的拦截器来处理所有的请求。

示例代码：

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**") // 所有路径
            .allowedOrigins("*") // 允许任何域名发送的请求
            .allowedMethods("PUT", "DELETE", "POST", "GET") // 允许的请求方法
            .maxAge(3600); // 预检请求的有效期，单位秒
    }
}
```

这种方法会配置全局的CORS支持，允许任何来源的请求，并且指定了允许的方法类型。

#### 注意事项：

- 使用`"*"`作为`allowedOrigins`可能会带来安全风险，因为它允许任何网站向你的API发送请求。在生产环境中，最好明确列出允许的来源。
- 如果你需要支持凭据（如cookies），则必须显式地设置`allowCredentials`为`true`。注意，一旦启用凭据支持，`allowedOrigins`就不能再设置为`"*"`，必须指定具体的来源。
- 在开发过程中测试CORS配置时，确保浏览器或使用的工具（如Postman）正确设置了请求头中的`Origin`字段。如果没有这个字段，CORS检查不会触发，因此你可能无法验证配置是否正确工作。

选择适合你需求的方法来配置CORS，以确保你的应用能够正确处理来自不同源的请求。
